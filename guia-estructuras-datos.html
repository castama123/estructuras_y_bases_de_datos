Antes de empezar: ¿las construyo yo o ya vienen hechas?

Esta es la duda más común, así que va primero: casi siempre ya vienen hechas. Python, Java y las bases de datos traen estas estructuras por dentro, y tú solo las llamas con el nombre correcto. Que no las construyas no significa que no las uses: las usas todo el tiempo. Escribir una lista enlazada o un árbol desde cero se hace en clase para entender cómo funcionan, no porque lo vayas a repetir en cada proyecto.

Entonces, ¿para qué estudiarlas? Para elegir bien. Usar una list como cola funciona, pero se vuelve lenta con muchos datos; con un deque no. Saber por qué un índice acelera un WHERE o por qué un LIKE '%Amor%' no lo aprovecha también sale de aquí.

1. Arreglos

Una fila de casillas numeradas, una al lado de la otra.

Es la estructura más simple y la base de casi todas las demás.

Qué operaciones tiene y cuánto cuestan

OperaciónCosto
Leer canciones[1] por posiciónO(1)
Agregar al finalO(1) en promedio
Insertar al inicio o en medioO(n): hay que correr los demás
Buscar un valor (desordenado)O(n)
Buscar un valor (ordenado)O(log n) con búsqueda binaria
Eliminar en medioO(n)

¿Cuándo usarla y cuándo evitarla?

✓ Úsala cuando...

  • Necesitas leer por posición muy seguido ("la canción número 3").
  • Tienes una colección de tamaño casi fijo que casi no cambia: un top 10, un tablero, los días de la semana.
  • Vas a buscar mucho y modificar poco: ordénalo una vez y usa búsqueda binaria.
  • Procesas muchos números seguidos: píxeles, embeddings, mediciones.

✗ Evítala cuando...

  • Insertas o eliminas mucho al inicio o en medio: cada cambio corre todos los demás elementos.
  • Buscas muchas veces por valor en un arreglo grande y desordenado: usa un set o un dict.
  • Cada elemento es un registro con varios campos (nombre, email, plan): usa una clase, un dict o una tabla.

¿Dónde se usa en aplicaciones y sistemas?

  • Hojas de cálculo: las filas y columnas son una matriz.
  • Imágenes y video: una imagen es un arreglo de píxeles (lo procesan librerías como NumPy y OpenCV).
  • Videojuegos: el tablero de ajedrez o de Sudoku, y las tablas de puntuaciones.
  • Inteligencia artificial: los embeddings son arreglos de números (los que usa pgvector en SoundFlow).

2. Listas enlazadas

Una cadena de cajas: cada caja guarda un dato y dice dónde está la siguiente.

Gana cuando insertas o eliminas mucho en medio de los datos, porque solo se cambian unos punteros.

Qué operaciones tiene y cuánto cuestan

OperaciónCosto
Leer el elemento número kO(n): hay que recorrer desde la cabeza
Insertar al inicioO(1)
Insertar al finalO(n), o O(1) si guardas un puntero a la cola
Eliminar un nodo que ya tienes en la manoO(1)
Buscar un valorO(n)

¿Cuándo usarla y cuándo evitarla?

✓ Úsala cuando...

  • Insertas o eliminas mucho al inicio o en medio, y ya tienes el nodo en la mano.
  • Necesitas moverte hacia adelante y hacia atrás (lista doblemente enlazada): una playlist.
  • No sabes cuántos datos habrá y la cantidad sube y baja todo el tiempo.
  • Vas a construir otras estructuras encima: pilas, colas o tablas hash con colisiones.

✗ Evítala cuando...

  • Necesitas acceso por posición: llegar al elemento 100 obliga a pasar por los 99 anteriores.
  • Buscas mucho por valor: recorrer la cadena es O(n).
  • En Python, para casi todo: list o deque hacen el trabajo sin que escribas una clase.

¿Dónde se usa en aplicaciones y sistemas?

  • Reproductores de música: "anterior" y "siguiente" funcionan con una lista doblemente enlazada.
  • Navegadores y editores: historial de páginas y de cambios encadenados.
  • Sistemas operativos: el núcleo de Linux usa listas enlazadas para procesos y bloques libres de memoria.
  • Cachés LRU: una tabla hash más una lista doblemente enlazada para sacar lo menos usado.

lista_enlazada.py 
class Nodo:
    def __init__(self, cancion):
        self.cancion = cancion      # el dato de este nodo
        self.siguiente = None       # todavía no apunta a nadie

class ListaEnlazada:
    def __init__(self):
        self.cabeza = None          # lista vacía

    def agregar(self, cancion):     # agrega al final
        nuevo = Nodo(cancion)
        if self.cabeza is None:
            self.cabeza = nuevo
            return
        actual = self.cabeza
        while actual.siguiente:     # avanza hasta el último nodo
            actual = actual.siguiente
        actual.siguiente = nuevo    # lo conecta

    def recorrer(self):
        actual = self.cabeza
        while actual:
            print(actual.cancion)
            actual = actual.siguiente

historial = ListaEnlazada()
historial.agregar("Tres Deseos")
historial.agregar("Mi Tierra")
historial.agregar("Mi Buen Amor")
historial.recorrer()                # imprime las tres, en orden

En un proyecto real normalmente usarías from collections import deque en vez de escribir esta clase. La clase se programa para aprender cómo funcionan los punteros.

-- Crear un índice: el motor lo guarda como un B+Tree.

-- Un rango como este puede recorrer las hojas enlazadas del índice, una tras otra.
SELECT titulo, reproducciones
FROM tbl_canciones
WHERE reproducciones BETWEEN 5000000 AND 15000000;

Tú no ves la lista enlazada: el motor la usa por dentro para recorrer rangos sin volver a empezar desde la raíz. Si el optimizador la usa o no depende del motor y de cuántas filas tenga la tabla.

¿La uso o la tengo que construir? La usas con deque. Casi nunca la construyes: eso se hace para aprender, o en casos muy especiales de bajo nivel.

Ojo: no hay acceso directo por posición. Para llegar al nodo 100 tienes que pasar por los 99 anteriores. Y si pierdes la cabeza, pierdes toda la lista.

3. Pilas (LIFO)

Una pila de platos: el último que pones es el primero que sacas.

Úsala cuando importe el orden inverso: lo último que entró es lo primero que necesitas.

Qué operaciones tiene y cuánto cuestan

OperaciónCosto
push: poner encimaO(1)
pop: sacar el de encimaO(1)
peek: mirar el de encima sin sacarloO(1)
Buscar algo en la pilaO(n)

¿Cuándo usarla y cuándo evitarla?

✓ Úsala cuando...

  • Hay que deshacer en orden inverso: lo último que hiciste se revierte primero.
  • Vuelves atrás por donde viniste: backtracking, recursión, el botón "atrás".
  • Validas cosas anidadas: paréntesis, llaves, etiquetas HTML.
  • Recorres un grafo o un árbol en profundidad (DFS) sin recursión.

✗ Evítala cuando...

  • Necesitas atender por orden de llegada: eso es una cola.
  • Necesitas llegar a un elemento del medio: una pila solo deja ver el de encima.
  • Necesitas recorrer en el orden en que se guardaron.

¿Dónde se usa en aplicaciones y sistemas?

  • Deshacer y rehacer: Word, Photoshop y VS Code guardan tus acciones en una pila.
  • Botón "atrás" del navegador.
  • Cada lenguaje tiene una pila de llamadas: cuando una función llama a otra, se apila.
  • Validar paréntesis o etiquetas HTML, evaluar expresiones y resolver Sudokus (backtracking).

¿Cómo la usas en un lenguaje de programación?

Tampoco la construyes: la list de Python ya hace de pila.

¿Cómo la usas en una base de datos?

DóndeCómo apareceQué haces tú
SQL (transacciones)SAVEPOINT y ROLLBACK TO se comportan parecido a una pila.Marcas puntos con SAVEPOINT y vuelves con ROLLBACK TO.
RedisUn LIST usado por un solo extremo.LPUSH para apilar y LPOP para sacar.
El motor de consultasUsa pilas al analizar consultas SQL anidadas.No haces nada: es interno.
savepoint.sql 
START TRANSACTION;
INSERT INTO tbl_pagos_suscripcion (monto, id_usuario) VALUES (25000, 1);
SAVEPOINT despues_del_pago;

UPDATE tbl_usuarios SET estado_activo = 0 WHERE idusuario = 1;
ROLLBACK TO despues_del_pago;     -- deshace solo el UPDATE; el INSERT sigue en pie
COMMIT;

Es una comparación, no una pila literal: los savepoints permiten volver a un punto anterior, y lo último que hiciste se deshace primero. Tiene que ver con el ROLLBACK que viste en las transacciones.

¿La uso o la tengo que construir? La usas tal cual: list ya es una pila.

Ojo: pop() sobre una pila vacía lanza IndexError. Revisa if pila: antes de sacar.

4. Colas (FIFO)

La fila del banco: el primero en llegar es el primero en ser atendido.

Úsala cuando importe el orden de llegada.

Qué operaciones tiene y cuánto cuestan

OperaciónCosto
Encolar (entrar por el final)O(1)
Desencolar (salir por el frente)O(1) con deque
Ver quién está de primeroO(1)
Desencolar con list.pop(0)O(n): evítalo

¿Cuándo usarla y cuándo evitarla?

✓ Úsala cuando...

  • Hay que atender por orden de llegada: turnos, pedidos, peticiones.
  • Tienes tareas pendientes que otro proceso va a ir sacando una por una.
  • Recorres un grafo por niveles (BFS) o procesas "primero los más cercanos".
  • Quieres amortiguar picos: guardar lo que llega mientras algo más lento lo procesa.

✗ Evítala cuando...

  • Lo último que entra debe salir primero: eso es una pila.
  • Algunos elementos son más urgentes que otros: necesitas una cola de prioridad (heapq).
  • Necesitas buscar un elemento que está en medio de la fila.

¿Dónde se usa en aplicaciones y sistemas?

  • Colas de tareas en segundo plano: Celery en Python, RabbitMQ, Amazon SQS.
  • Kafka: registra eventos en orden, y varios consumidores los leen en ese orden.
  • Cola de impresión, peticiones a un servidor web y buffer de streaming de música o video.
  • Planificador de procesos de un sistema operativo.

¿Cómo la usas en un lenguaje de programación?

LenguajeCómo se llamaCómo se escribe
Pythoncollections.dequecola.append(x) y cola.popleft()

La cola también viene hecha, y la usas con deque. Es la estructura que usa el BFS.

RabbitMQ, Kafka, SQSNo son bases de datos tradicionales: son sistemas hechos para colas y eventos.Publicas mensajes y otro programa los consume.

¿La uso o la tengo que construir? La usas tal cual: deque ya es una cola.

Ojo: popleft() sobre un deque vacío lanza IndexError. Y no uses list.pop(0) en colas grandes.

5. Grafos

Cosas (nodos) conectadas por relaciones (aristas).

Úsalo cuando lo importante son las relaciones entre las cosas.

Qué operaciones tiene y cuánto cuestan

OperaciónCosto
Agregar un nodo o una arista (lista de adyacencia)O(1)
Ver los vecinos de un nodoO(grado del nodo)
Saber si dos nodos están conectados (lista)O(grado); con matriz O(1)
Recorrer todo (BFS o DFS)O(V + E): nodos más aristas

¿Cuándo usarla y cuándo evitarla?

✓ Úsala cuando...

  • Lo importante son las relaciones entre las cosas: amigos, colaboraciones, rutas, dependencias.
  • Preguntas como "¿cómo llego de A a B?" o "¿quién está conectado con quién?".
  • Las relaciones son muchos a muchos y te interesan los caminos de varios saltos.
  • Quieres recomendar algo a partir de lo que hicieron usuarios parecidos.

✗ Evítala cuando...

  • Los datos son independientes y no se relacionan: una tabla o una lista basta.
  • La relación es de un solo nivel: un JOIN lo resuelve sin armar un grafo.
  • Es una jerarquía estricta (cada elemento tiene un solo padre): eso es un árbol.

¿Dónde se usa en aplicaciones y sistemas?

  • Redes sociales: LinkedIn, Facebook e Instagram modelan personas conectadas por amistades o seguidores.
  • Mapas y rutas: Google Maps y Waze buscan el camino más corto sobre un grafo de calles.
  • Git: el historial de commits es un grafo. Los gestores de paquetes (npm, pip) resuelven dependencias con grafos.
  • Detección de fraude y recomendaciones: relacionan usuarios con lo que compran o escuchan.

¿Cómo la usas en un lenguaje de programación?

LenguajeCómo se llamaCómo se escribe
Pythondict de listas, o la librería networkxgrafo = {"SHA": ["BIZ", "KAR"]}

grafo.py 
from collections import deque

# Lista de adyacencia: cada artista con la lista de quienes colaboraron con él
grafo = {
    "SHA": ["BIZ", "KAR"],
    "BIZ": ["SHA", "QUE"],
    "QUE": ["BIZ"],
    "KAR": ["SHA", "JBA"],
    "JBA": ["KAR", "BAD", "DUA", "ROS"],
    "BAD": ["JBA", "DUA"],
    "DUA": ["BAD", "JBA", "ELT"],
    "ELT": ["DUA"],
    "ROS": ["JBA", "RAU"],
    "RAU": ["ROS"],
}

def bfs(grafo, inicio):                 # recorrido en anchura: usa una COLA
    visitados = {inicio}
    cola = deque([inicio])
    while cola:
        nodo = cola.popleft()
        print(nodo, end=" ")
        for vecino in grafo[nodo]:
            if vecino not in visitados:
                visitados.add(vecino)
                cola.append(vecino)

bfs(grafo, "SHA")     # SHA BIZ KAR QUE JBA BAD DUA ROS ELT RAU

# Con la librería networkx (pip install networkx):
import networkx as nx
G = nx.Graph(grafo)                     # acepta el dict directamente
print(nx.shortest_path(G, "SHA", "ELT"))   # ['SHA', 'KAR', 'JBA', 'DUA', 'ELT']
print(G.degree("JBA"))                  # 4

Normalmente tú armas la estructura (el dict) y el recorrido, o dejas que networkx lo haga. BFS usa una cola y DFS usa una pila.

DóndeCómo apareceQué haces tú

grafo_de_reproducciones.sql 
-- Cada fila de tbl_reproducciones es una arista: usuario -> canción.
SELECT id_usuario, id_cancion
FROM tbl_reproducciones;

-- Grado de cada canción: a cuántos usuarios está conectada.
SELECT id_cancion, COUNT(*) AS grado
FROM tbl_reproducciones
GROUP BY id_cancion
ORDER BY grado DESC;

Es el mismo grafo de la práctica: los usuarios y las canciones son los nodos, y cada fila de la tabla es una arista. En SQL no se "dibuja" el grafo, se consulta la tabla que lo representa.

¿La uso o la tengo que construir? La usas: armas la estructura tú (un dict basta) o usas una librería como networkx.

Ojo: si no marcas los nodos visitados, el recorrido da vueltas para siempre en los ciclos. Y en un grafo sin dirección, cada conexión se guarda en las dos listas (A tiene a B y B tiene a A).

6. Árboles

Una jerarquía: una raíz de la que salen ramas, y cada rama puede tener más ramas.

Úsalo para jerarquías y para buscar rápido en datos ordenados.

Qué operaciones tiene y cuánto cuestan

OperaciónCosto
Buscar, insertar o eliminar (árbol balanceado)O(log n)
Lo mismo en un árbol desbalanceado (peor caso)O(n)
Recorrer todos los nodosO(n)

¿Cuándo usarla y cuándo evitarla?

✓ Úsala cuando...

  • Tus datos son una jerarquía: carpetas, categorías, organigramas, comentarios con respuestas.
  • Necesitas buscar rápido en datos ordenados y que se insertan seguido.
  • Necesitas recorrer en orden o por rangos (BETWEEN, "los mayores que 50").
  • Necesitas siempre el menor o el mayor elemento (montículo, heapq).

✗ Evítala cuando...

  • Tienes pocos datos: una lista ordenada basta.
  • Los datos no tienen jerarquía ni orden que aprovechar.
  • Un elemento puede tener varios padres o formar ciclos: eso es un grafo.

¿Dónde se usa en aplicaciones y sistemas?

  • Sistemas de archivos: las carpetas de Windows y Linux forman un árbol.
  • Páginas web: el DOM de HTML es un árbol de etiquetas. JSON y XML también.
  • Organigramas, categorías de una tienda y comentarios anidados.
  • Compiladores e intérpretes: convierten tu código en un árbol (AST) antes de ejecutarlo.

    def __init__(self, valor):
        self.valor = valor
        self.izquierdo = None       # hijos menores
        self.derecho = None         # hijos mayores

def insertar(raiz, valor):
    if raiz is None:
        return NodoArbol(valor)
    if valor < raiz.valor:
        raiz.izquierdo = insertar(raiz.izquierdo, valor)
    else:
        raiz.derecho = insertar(raiz.derecho, valor)
    return raiz

def buscar(raiz, valor):
    if raiz is None:
        return False
    if valor == raiz.valor:
        return True
    siguiente = raiz.izquierdo if valor < raiz.valor else raiz.derecho
    return buscar(siguiente, valor)  # descarta la mitad de los nodos en cada paso

raiz = None
for v in [50, 30, 70, 20, 40, 60, 80]:
    raiz = insertar(raiz, v)

print(buscar(raiz, 60))             # True
print(buscar(raiz, 65))             # False

Solo la programas si tu problema es jerárquico. Para buscar rápido en una base de datos no escribes un árbol: creas un índice y el motor ya lo usa.

7. Tries (árboles de prefijos)

Un árbol donde cada nivel es una letra y cada camino de la raíz forma una palabra.

Úsalo cuando necesites buscar o autocompletar por prefijo en muchas palabras.

Qué operaciones tiene y cuánto cuestan

OperaciónCosto
Insertar una palabraO(L), con L = largo de la palabra
Buscar una palabraO(L), sin importar cuántas palabras haya
Buscar todo lo que empieza con un prefijoO(L) para llegar al prefijo, más lo que devuelva

¿Cuándo usarla y cuándo evitarla?

✓ Úsala cuando...

  • Necesitas autocompletar o buscar por prefijo en muchas palabras.
  • Quieres saber rápido si una palabra existe en un diccionario grande.
  • Enrutas por prefijos: direcciones IP, rutas de URL.
  • Muchas palabras comparten el mismo comienzo, y por eso el trie ahorra comparaciones.

✗ Evítala cuando...

  • Tienes pocas palabras: una lista con startswith() es más simple.
  • Buscas texto que "contenga" algo en cualquier parte: el prefijo no ayuda.
  • La memoria es limitada: el trie guarda un nodo por letra.

¿Dónde se usa en aplicaciones y sistemas?

  • Autocompletado del buscador y teclado predictivo del celular.
  • Correctores ortográficos y diccionarios.
  • Tablas de enrutamiento de IP: los routers buscan el prefijo de red más largo.
  • Algunos frameworks web buscan la ruta de una URL con árboles de prefijos.

class NodoTrie:
    def __init__(self):
        self.hijos = {}           # letra -> NodoTrie
        self.es_final = False     # ¿aquí termina una palabra?

class Trie:
    def __init__(self):
        self.raiz = NodoTrie()

    def insertar(self, palabra):
        nodo = self.raiz
        for letra in palabra:
            nodo = nodo.hijos.setdefault(letra, NodoTrie())
        nodo.es_final = True

    def autocompletar(self, prefijo):
        nodo = self.raiz
        for letra in prefijo:         # baja siguiendo el prefijo
            if letra not in nodo.hijos:
                return []
            nodo = nodo.hijos[letra]
        resultados = []
        def recorrer(n, camino):
            if n.es_final:
                resultados.append(camino)
            for letra, hijo in n.hijos.items():
                recorrer(hijo, camino + letra)
        recorrer(nodo, prefijo)
        return resultados

t = Trie()
for titulo in ["Mi Tierra", "Mi Buen Amor", "Oye Mi Amor", "Tres Deseos"]:
    t.insertar(titulo)

print(t.autocompletar("Mi "))        # ['Mi Tierra', 'Mi Buen Amor']

Con pocos datos no hace falta: una list con startswith() resuelve el autocompletado. El trie vale la pena con muchas palabras y muchas búsquedas.

Preguntas frecuentes

¿Tengo que programar estas estructuras desde cero en un trabajo real?

Casi nunca. Los lenguajes y las bases de datos ya las traen. Se programan en clase para que entiendas cómo funcionan por dentro y puedas elegir bien la que ya existe.

¿Python tiene lista enlazada?

No como un tipo de uso general. collections.deque usa por dentro una lista doblemente enlazada de bloques, y es lo que se usa en la práctica. La clase Nodo de la guía sirve para aprender.

¿SQL tiene pilas, colas o grafos?

No como tipos. Se representan: un grafo es una tabla de relaciones, una cola puede ser una tabla de tareas pendientes, y SAVEPOINT se parece a una pila. Redis sí tiene listas que sirven como pila o cola.

Mi programa se vuelve lento con listas grandes, ¿qué reviso?

Tres cosas: buscar con in sobre una lista es O(n) (usa un set o un dict); list.pop(0) es O(n) (usa un deque); e insertar en medio de una lista grande corre todos los elementos.

¿Una base de datos es una tabla, un árbol o qué?

Una tabla es el modelo lógico que tú ves. Por dentro, el motor usa otras estructuras: árboles B+Tree para los índices, páginas de datos en disco, listas enlazadas, tablas hash, colas de transacciones. Tú pides con SQL y el motor decide cómo guardarlo.
